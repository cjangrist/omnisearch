# AGENTS.md — src/server/

Tool and REST orchestration. Two orchestrators (search fanout, omnifetch client), three REST endpoints, and the MCP tool registry.

## Files

- **`tools.ts`** — MCP tool registration. Defines a `ToolRegistry` singleton (module-scoped) holding the `web_search_provider` (the `fetch` tool is backed by the external omnifetch service — no internal provider registry, just `fetch_url` from `omnifetch_client.ts`). `register_tools(server, get_ctx)` wires two tools — `web_search` and `fetch` — onto an `McpServer`; the fetch tool is registered whenever `omnifetch_available()` is true. Each tool callback closes over the per-DO `get_ctx` getter (R4F01) so trace `flush_background` writes attach to the DO's `waitUntil`. Tool input/output schemas use Zod. The `fetch` tool takes only `{ url }`. The `web_search` tool also accepts a `grounded_snippets?: boolean` input flag and returns each `web_results[i].snippet_source` ∈ `{ aggregated, grounded, fallback }` so callers can see which path produced each snippet.
- **`handlers.ts`** — MCP resource handlers (provider-status, provider-info). Read-only resources reflecting the active set.
- **`web_search_fanout.ts`** — `run_web_search_fanout(unified, query, options)` parallel-fans-out the query to every active search provider. Calls `rank_and_merge` (RRF + dedup + tail rescue + quality filter) and `collapse_snippets`. After ranking, when `CEREBRAS_API_KEY` is set, the top-N URLs are passed to `ground_top_results` from `grounded_snippets.ts`; grounded snippets replace the engine-supplied ones and the rest of the ranked list is appended unchanged. Per-call opt-out via `options.grounded_snippets === false`. KV cache key is `hash_key('search:', query [+ '\0sqf=true'] [+ '\0gnd=true'])` — the grounded suffix prevents cross-mode collisions so a `grounded:false` raw call can't poison subsequent grounded calls or vice versa. Optional `timeout_ms` aborts pending providers at the deadline. Only complete fanouts (no failures, no aborts) are cached.
- **`grounded_snippets.ts`** — orchestrates the grounding stage. Public entry: `ground_top_results(query, results, signal?)`. Bounded worker pool (default `concurrency = 10`) — each worker fetches a URL through `fetch_url` (the omnifetch client) and calls Cerebras (`gpt-oss-120b`) via `http_json` to write a query-framed snippet. Per-URL hard deadline (default `per_url_deadline_ms = 7500`) fires an `AbortController` whose signal is threaded into the inner fetch + Cerebras calls so a slow URL never stalls a worker past the cap. Pre-LLM junk-content detection (paywall / login-wall / cookie-wall / JS-shell / bot-challenge — see `grounded_prompts.ts`) and post-LLM sentinel detection (`[no usable content]`, `[navigation only]`, etc.) NO LONGER trigger a retry — a single fetch is performed per URL, and junk/sentinel content falls back to the original aggregated snippet. Outcomes are classified into 8 buckets (`GroundingOutcome`: `grounded`, `fallback:fetch_exhausted`, `fallback:fetch_too_short`, `fallback:fetch_junk`, `fallback:llm_sentinel`, `fallback:llm_error`, `fallback:llm_empty`, `fallback:pipeline_timeout`; `fallback:worker_rejected` also appears in the aggregate for unexpectedly-rejected workers). Emits structured per-phase logs (`op: 'grounding_phase'`) plus a single `grounding_aggregate` line per call with grounded ratio, p50/p95/max latency, provider wins, and timeout count. Also runs `close_unbalanced_fence` over the snippet so a model truncation mid-fence can't bleed downstream markdown. Successful snippets set `result.snippet_source = 'grounded'`; failures set `'fallback'` and leave the original aggregated snippet in place.
- **`grounded_prompts.ts`** — prompt + heuristic surface kept separate from the orchestrator so prompt iteration is low-blast-radius. Exports `GROUNDED_SYSTEM_PROMPT` (content-type-routed snippet writer with INVARIANTS — anti-preface forbidden-opener list, prompt-injection defense, language preservation), `build_grounded_user_message(query, title, content, max_chars)`, `GROUNDED_SNIPPET_MAX_CHARS = 2000`, and the junk + sentinel detectors. Junk patterns are split into `GROUNDED_JUNK_TIGHT_PATTERNS` (always fire) and `GROUNDED_JUNK_AMBIGUOUS_PATTERNS` (length-gated to ≤ 3000 chars so long-form prose mentioning "access denied" or "security check" rhetorically isn't retried for nothing). Sentinels (`[no usable content]`, `[navigation only]`, `[page not found]`, `[search results page]`, `[login required]`) — `detect_grounded_sentinel` strips trailing punctuation + markdown wrap chars before exact match, then falls back to a length-gated (≤ 200 chars) substring match for prose-framed sentinels.
- **`omnifetch_client.ts`** — thin client for the external [omnifetch](https://github.com/cjangrist/omnifetch) service. omnisearch no longer runs a fetch waterfall internally; this module is the single point of contact. Exports `fetch_url(url, signal?)` (POST `{url}` to `${OMNIFETCH_ENDPOINT}/web_fetch`, returns `{ url, title, content, source_provider, total_duration_ms, metadata? }`) and `omnifetch_available()` (`!!OMNIFETCH_ENDPOINT`). Errors from omnifetch surface as `ProviderError` (mapped by `http_json` from the HTTP status) so REST status mapping and MCP `format_error` work unchanged. The waterfall, breakers, multi-winner race, and `skip_providers` all live in omnifetch — not here. No fetch-side KV cache (fetch does not cache in omnisearch).
- **`rest_search.ts`** — `POST /search`. Body: `{ query, count?, raw?, grounded_snippets? }`. `count` clamped to 0..100 (0 = all). `raw: true` skips quality filtering. `grounded_snippets: false` opts the call out of the Cerebras grounding stage (default ON when `CEREBRAS_API_KEY` is configured). Returns `[{ link, title, snippet }]`. 502 + `{ error, failed_providers }` if all providers failed.
- **`rest_fetch.ts`** — `POST /fetch`. Body: `{ url }`. Delegates to `fetch_url` (omnifetch). Returns `{ url, title, content, source_provider, duration_ms, metadata }`. 65536-byte body guard, plus URL format + length (max 2000 chars) validation. Errors map to 400 / 404 / 429 / 502 via the usual `ProviderError` type switch. No cache (fetch is not cached in omnisearch).
- **`rest_researcher.ts`** — `GET` or `POST /researcher`. Auth via `Authorization: Bearer ...` OR `?api_key=...` query param. Body or query param `query`. Returns up to 10 search snippets shaped as `[{ href, body }]` for GPT-Researcher's `RETRIEVER=custom` integration. **Snippets only — no full-page fetch happens** (the file's older header comment is misleading; the implementation calls only `run_web_search_fanout`).

## Conventions / Invariants

- **Both orchestrators wrap their work in `run_with_trace(ctx, fn)`** so providers can call `get_active_trace()?.record_*` without threading.
- **Failure isolation per provider** — every fanout / waterfall step has its own try/catch. One provider's exception never crashes the rest.
- **Partial fanouts are NOT cached** — the cache validator stores `query` / `requested_url`, but partial fanouts skip the write entirely.
- **Cancellation propagates**: `make_signal(timeout, external)` combines an external signal with the per-provider timeout. The fanout's deadline is one such external signal.
- **`is_done` flag pattern** for late arrivals — once the search orchestrator settles, late-arriving promises check `is_done` and skip mutating result arrays.
- **Error model**: throw `ProviderError` from inside provider implementations; orchestrators convert to `providers_failed` entries. REST handlers convert top-level `ProviderError(INVALID_INPUT)` to 400 and others to 502.

## Gotchas / History

- **The `kimi` search provider requires both `KIMI_API_KEY` AND `SCRAPFLY_API_KEY`.** If only one is set, kimi is silently skipped at the active-set filter (correct behavior). Scrapfly config is now top-level (`config.scrapfly`), not `config.fetch.scrapfly`.
- **`/researcher` returns snippets, not full content** despite an older header comment. If you need full extraction, call `/fetch` separately or the MCP `fetch` tool.
- **R4F01 (per-DO ctx capture)** is a tools.ts-specific invariant. The registry is module-scoped (shared across DO instances in the same isolate); each tool closure captures its own `get_ctx` so trace flush_background calls scope to the right DO. See README's "Concurrency model" section.
- **All-failed → 502, not 200** on REST `/search` and `/researcher`. (R3F03)
- **Grounded snippets default to ON when `CEREBRAS_API_KEY` is set.** Both the MCP `web_search` tool and `POST /search` accept a `grounded_snippets: false` opt-out. The grounding stage imports `fetch_url` directly from `omnifetch_client.ts` — no fetch provider is threaded through the fanout. The cache key is salted with `\0gnd=true` so grounded and non-grounded modes share neither cache hits nor poisoning paths.
- **Grounding no longer retries on junk/sentinel content.** Previously a junk/sentinel detection triggered a single retry through the waterfall with `skip_providers`. That path was removed with the internal waterfall — now a single fetch per URL via omnifetch, and junk/sentinel content falls back to the aggregated snippet.
